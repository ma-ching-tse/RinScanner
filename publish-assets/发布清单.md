## 一、操作步骤（Figma 桌面端）

1. 在任意 Figma 文件里，菜单 **Plugins → Development → RinScanner**（先确认已用 manifest 导入过）
2. 同一菜单点 **Publish new release…**（首次发布）
3. 在发布弹窗里：
   - 顶部 **可见性** 选 **Only available to your organization / 仅本组织可见**（关键，否则就是公开）
   - 依次填入下方「文案区」的内容、上传「素材区」的图
4. 点 **Publish** → Figma 会给一个内部审核（组织内通常很快或免审）

> 之后改了代码要更新：同菜单 **Publish new release…** 再发一版即可，组织成员会自动拿到更新。

## 二、文案区（逐字粘贴）

### 插件名 Name
```
RinScanner
```

### 一句话简介 Tagline（列表页显示，建议 ≤ 60 字）
```
一键扫描 Figma 设计规范：未绑定 token 的颜色/字体、不规范布局、默认命名，并一键修复。
```

### 详细描述 Description（支持 Markdown）
```
RinScanner 扫描当前画板，找出没有遵循设计规范的地方，并直接帮你修好——让 Dev Mode / MCP 出码时生成 var(--token) 而不是硬编码值。

【检查三个维度】（顶部可多选）
• Token —— 颜色（fill/stroke）+ 字体，对照 BMDS 设计 token。修复优先绑定 Figma 变量，Dev Mode / MCP 出码即为 var(--token)，并自动按 light/dark 解析。
• 布局 —— 检测用了 Group、或多子元素 Frame 缺 auto-layout，定位到具体图层。
• 命名 —— 正则抓默认名（Frame 427 等）；可选接入 LLM 给语义化 PascalCase 建议并一键改名。

【匹配等级】
• 完全匹配 → 一键应用
• 相近匹配（颜色 ΔRGB ≤ 8）→ 提示后替换
• 部分匹配（字体仅 family+size 一致）→ 候选列表
• 无匹配 → 仅报告

【组件实例智能跳过】
• 设计系统库组件（远程库）整体跳过——token 化是库的职责
• 本地组件实例只检测手动 override
• 支持按组件名手动加白名单（存本机，跨文件通用）

【AI 命名（实验）】
在 ⚙ 设置里填入 OpenAI 兼容的代理地址 / 模型 / API Key（Qwen DashScope compatible-mode 可用）。配置存本机 clientStorage，不上传。命名时把图层类型/当前名/父层名/内部文字批量发给模型，返回建议供你逐条采纳。不发送截图。

【使用】
1. 选中一个或多个画板/节点
2. 运行 RinScanner → 点「扫描」
3. 逐项点「应用 token」/「改名」修复

【数据与隐私】
本插件会向团队自有服务器发送匿名/实名的用量统计（扫描数量、命中数量、文件名、用户名等数值摘要），用于了解使用情况；不发送任何设计内容、图层内容或截图。AI 命名功能仅在你主动点击时、向你自己配置的端点发送图层文本。详见隐私说明链接。
```

## 五、关键提醒

1. **可见性一定选「仅组织可见」**——默认是公开，选错就全网可见了。
2. **遥测发往裸 IP/sslip.io**：组织内发布 Figma 一般不深审，但若日后想转公开，这个端点 + 实名采集需要换成正式域名 + 隐私政策（见记忆 [[token-scanner-telemetry]]）。
3. **BMDS token 写死**：插件只对订阅了 BMDS 变量库的文件有效，这点已与「BitMart 专用」定位一致。
